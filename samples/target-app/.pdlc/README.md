# `.pdlc/` — Continuum Pipeline Artifacts

This directory is written by the **Continuum** agentic SDLC pipeline (Layer 1)
into your application repo (Layer 2) at the end of every pipeline run.

## Contents

| File / Directory | What it contains |
|---|---|
| `run_manifest.json` | Run metadata: run_id, feature request, status, model cost, business-mapping fidelity |
| `evidence.json` | 6-layer Evidence Stack: build, regression, acceptance, scope conformance, SAST, human review |
| `contracts/openapi.yaml` | OpenAPI 3.x contract generated by the Architect agent |
| `contracts/schema.sql` | SQL DDL generated by the Architect agent |
| `generated/` | Code files produced by the DATABASE → BACKEND → FRONTEND agent chain |

## Two-Layer Architecture

```
Layer 1 — Process (Continuum repo)
  orchestrator/   agents/   skills/   evals/   ui/
        │
        │  emit_pdlc_artifacts()
        ▼
Layer 2 — Product (this repo)
  src/    tests/    .pdlc/   ← Continuum writes here
```

The separation means:
- Continuum (Layer 1) is never modified by the pipeline it runs.
- Your application (Layer 2) accumulates an auditable history of every run via `.pdlc/`.
- You can commit `.pdlc/` to git for traceability, or `.gitignore` it to keep the
  run history in the Continuum server only.
